# Supabase Setup & Restoration Guide

This guide provides the definitive steps to set up, update, or reset your Studio database environment (Local and Remote).

---

## 🏗 Scenario 1: Fresh Local Setup (New Machine)
Use this when you have no project running locally.

1. **Start Supabase**:
   ```bash
   npx supabase start
   ```
   *This will automatically create all tables and storage buckets (`photos`, `avatars`).*

2. **Seed System Data**:
   Open your local Supabase Studio (`http://localhost:54323`).
   In the **SQL Editor**, execute the contents of:
   - **[full-system-setup.sql](file:///c:/Users/Eitan%20Baron/Documents/GitHub/studio/supabase/full-system-setup.sql)**

3. **Verify**:
   Log in at `http://localhost:9002` with:
   - **Email**: `admin@test.com`
   - **Password**: `password123` (Standard for test accounts)

---

## 🛠 Scenario 2: Remote DB Cleanup & Restoration
Use this to bring your remote database to the exact same state as your local machine.

1. **Cleanup**:
   In the remote Dashboard SQL Editor, execute:
   - **[factory-reset.sql](file:///c:/Users/Eitan%20Baron/Documents/GitHub/studio/supabase/factory-reset.sql)**
   *Warning: This wipes everything but keeps the tables.*

2. **Restoration**:
   In the remote Dashboard SQL Editor, execute:
   - **[full-system-setup.sql](file:///c:/Users/Eitan%20Baron/Documents/GitHub/studio/supabase/full-system-setup.sql)**

3. **Check Categories**:
   If the `categories` table (legacy) is missing, don't worry. The system now uses `template_categories`.

## 📦 Storage Buckets
The following buckets are required and generated by migrations:
- `photos`: Public bucket for album photos.
- `avatars`: Public bucket for user profile pictures.

If they are missing for some reason, re-run migrations or use:
```sql
INSERT INTO storage.buckets (id, name, public) VALUES ('photos', 'photos', true) ON CONFLICT DO NOTHING;
INSERT INTO storage.buckets (id, name, public) VALUES ('avatars', 'avatars', true) ON CONFLICT DO NOTHING;
```
